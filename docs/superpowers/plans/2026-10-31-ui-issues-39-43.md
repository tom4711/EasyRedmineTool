# UI Issues 39–43 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement the tasks in this shared, already-modified worktree. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the remaining UI improvements in GitHub Issues #39–#43 on the current Sammelbranch.

**Architecture:** Keep each change in its existing view and ViewModel. The weekly summary receives an explicit relative-scale explanation and selectable quarter state; settings gain separate edit, save, and connection-test states; series confirmation is generated from the exact booking selection; delete confirmation uses a reusable destructive style.

**Tech Stack:** .NET, C#, Avalonia XAML, CommunityToolkit.Mvvm.

**Spec:** GitHub Issues [#39](https://github.com/tom4711/EasyRedmineTool/issues/39), [#40](https://github.com/tom4711/EasyRedmineTool/issues/40), [#41](https://github.com/tom4711/EasyRedmineTool/issues/41), [#42](https://github.com/tom4711/EasyRedmineTool/issues/42), [#43](https://github.com/tom4711/EasyRedmineTool/issues/43).

## Global Constraints

- Keep each existing screen's data and actions available while adding the requested affordances.
- Ensure displayed quarter, series summary, and executed request derive from the same selected values.
- Keep the API key masked on opening and out of status text.
- Distinguish destructive delete from positive primary actions in both themes.
- Do not add or run tests unless requested; verify with the desktop build and UI inspection.

## Review Focus

- Quarter boundary and year rollover: show the correct selected dates and reject stale responses.
- Editing URL/key after a successful connection test: mark the prior result as stale.
- Series preview changes or excluded days: confirmation and submission use the same selected rows and totals.
- Busy delete request: prevent repeat submission while leaving an error recoverable.
- Empty weekly data: communicate relative scaling without presenting a full or target-like bar.
